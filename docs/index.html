Model Router field guide

The right model for each job, and the bill before you pay it.

  • Routes models by kind of work. Opus plans, Sonnet edits, Haiku searches: plan mode, normal work and each subagent type get their own model and effort.
  • Shows the cost as you go. Cache health, context, last prompt and plan limits above the prompt; today's spend below it.
  • Says when to compact or clear. After a commit, near auto-compact or on a cold cache, the band says what to do next, with the reason in dollars.
  • Spots what you don't use. MCP servers and plugins a repo never touches, with the exact setting that turns each off there.
  • Stops the expensive send. When the cache has gone cold over a big context, your next message is held once with its price.
  • Explains, if you want it to. Learn mode turns cache misses and model switches into short lessons with your own numbers.
/plugin install model-router --marketplace TFoxik/claude-model-router

Below is every part of the screen it adds. The numbers on each picture match the notes beside it; hover or tap either side to highlight the pair. All values are examples.

Source, issues and the full README: github.com/TFoxik/claude-model-router.

1

On / off

● on means the router picks the model and effort for every request. Turn off stops that, and everything uses the session's own model. Cost tracking, the band and the cold-send guard keep working either way. Same as /route on / /route off.

2

Learn mode

Off by default. Turn on starts the lessons described in Learn mode; the line under it disappears and the button becomes Turn off. Open shows the Learn pane. Same as /route learn on / off.

Auto-handoff

Off by default. When on, and the cache is in its last minutes with two or more steps open or a plan not yet started, model-router asks Claude for a handoff while the cache is still warm and saves the reply under ~/.claude/handoffs/<repo>/. It waits while you type or anything runs, goes once per prompt, and never clears the session. Same as /route handoff on / off.

Next-step advice

On by default. Shows next /clear, next /compact or next /handoff in the band when carrying on is not the best move, with the reason at the top of the Context pane's tips. Turn off hides both, and learn mode stops teaching from that advice. Same as /route next on / off.

5

Main loop

The model that talks to you directly. Plan mode is used while plan mode is on, Normal work the rest of the time. Each row has a model (Opus, Sonnet, Haiku, Fable, inherit) and an effort (low to max, inherit, or auto).

auto exists only here: it sends the start of each prompt to Haiku, which rates it trivial, standard or hard, and the effort follows. Changing a main-loop row rebuilds the prompt cache once, because a cache belongs to one model and effort. ▸ marks the live row.

6

Subagents

Helpers Claude starts. They begin with an empty context, so sending them to a cheaper model costs nothing up front.

Every subagent, unless a row below overrides it.

The read-only codebase search agent.
Plan agent
The agent that drafts implementation plans (separate from plan mode).
General
The general-purpose agent.
Workflow
Agents started by a multi-agent workflow.
Teammates
Agents running as teammates.

Other agent types use Default. Give one its own route with /route set sub:<agent-type> haiku low.

7

How inherit works

inherit means “use the row above”. Model and effort are looked up separately, walking up until a real value is found, then falling back to the session.

Plan mode → Normal work → session
Explore / Plan agent / General / Workflow / Teammates → Default → session

Forks, background copies of the current conversation, always use the parent's model.

in the conversation, when you send

Cold-send guard

The prompt cache expires after a pause (1 hour by default). Your next message then has to re-send the whole conversation at the cache-write price, which on a big context can be dollars instead of cents.

1model-router: the prompt cache went cold 1h12m ago. This send re-writes ~200k tokens on Opus 5.5 = $1.60 (warm would be $0.04). Send it again to pay it, or /clear and start from a note.

Why: Each request re-sends the whole conversation. A warm prompt cache lets the API read it back cheaply…
1

Your message is held once

When the cache is cold and the context is over 50k tokens, the mod drops your message once and tells you what it would cost. Send it again to go ahead, or start fresh with /clear.

Slash commands that reach the model (like /simplify) are held the same way. Notifications, triggers and messages from other sessions always pass.

/route guard refuse
Hold once with the price (default).
/route guard warn
Only show the price and send anyway.
/route guard off
No guard.

With learn mode on, the message adds a Why: paragraph explaining the cache. The guard uses the band's clock and doesn't keep the cache warm itself; see Stepping away for ways to avoid the cold send.

The toast

Appears when a lesson is worth your attention right now. The first time a topic comes up it starts with the topic's name; after that with ▸.

To stay out of the way: at most one toast per turn (the costliest lesson wins), each topic at most once an hour, and a topic stops toasting after three times. Lessons that don't toast still land in the pane. The band's Learn ●N button counts the ones that toasted and the first of each topic, not quiet repeats.

2

One card per topic

The pane shows lessons from This repo first; All shows every repo's, each fact starting with its repo. Mutes and learn mode itself are shared by all your sessions. Topics are ordered by their newest lesson. why? shows or hides the explanation. mute stops a topic you already know, such as the expensive-model lesson when you route Opus on purpose: no lessons, toasts or count for it. Muted topics are listed at the bottom; press one to unmute it.

1

Your session now

Context size, the model the next send is routed to, and how long the cache stays warm. Once it's cold, the report says so and points to /clear, which costs nothing.

2

Note and clear

The cheapest way back. One warm turn to have Claude write down the plan, decisions and next steps, then /rename so you can find the session and /clear. You come back to a small, fresh session that reads the note.

3

Compact while warm

Compaction reads the whole conversation; warm, that read is cheap. Tell it what to keep. On return only the short summary is written to a new cache. Compacting after the break is the expensive way: it reads everything at full price.

4

Rename and resume

Nothing now. On Pro and Max, resuming a big session after a long break offers to continue from a summary instead of the full history.

5

Keep warm

A tiny send before each expiry keeps the cache alive for one warm read per hour (twelve on the 5-minute cache). Worth it for a few hours away; overnight it adds up, and on a subscription it counts against your limits.

6

Do nothing

/route unused · tips in the Context pane

Unused servers and plugins

Every connected MCP server sends its tool names and instructions with each request, and every plugin adds its skills to the list Claude reads. The mod notes, per repo, which ones are loaded and which get used, and names the ones a repo leaves alone. It can't switch anything off itself; it gives you the setting that does.

3  › None of the 2 claude.ai connectors is used here: "disableClaudeAiConnectors": true in .claude/settings.local.json turns them all off for this repo.

1

What counts

A server is used when Claude calls one of its tools. A plugin is used when one of its skills, agents, slash commands or MCP tools runs. Recording starts with 0.7.0. Something is listed once it has been loaded here for two weeks and ten sessions with no use in the last 30 days. Each session counts once, even across a /login or a reload.

2

MCP servers

Named as /mcp names them. /mcp keeps a server off for the repo you turn it off in. A server no repo has used says so, and suggests removing it from its config. A connector you never signed in to only offers sign-in tools; it isn't counted as connected, so it's never listed.

3

claude.ai connectors

Connectors come with your claude.ai account and load in every repo. When none of the connected ones is used here, one setting turns them all off for this repo.

4

Plugins

A block to paste into the repo's .claude/settings.local.json, with each plugin's full name@marketplace. A plugin no repo uses points to /plugin instead. Turning a plugin off takes its own MCP server with it, so that server isn't listed again. The mod can't see a plugin's hooks run, so check before turning off one you keep for its hooks; plugins with nothing but hooks are never listed.

The Context pane shows the three biggest as tips. To try it without two weeks of history, start a session with MODEL_ROUTER_IDLE_DEV=1: after its first prompt, anything loaded but not used in the last 30 days is listed.

Good to know

  • A prompt cache belongs to one model and effort. Changing the route the main loop is on rebuilds it once; the pane shows that cost before you apply.
  • Subagents start with a fresh context, so cheaper subagent models save money from the first run.
  • auto effort makes one extra small Haiku request per prompt to rate it.
  • Learn mode is off by default and changes no routing; it only explains what the mod measures.
  • Model IDs are the Anthropic API's. On a provider that names models differently, turn routing off or use inherit.

Privacy

  • No network, file or process access of its own.
  • Prompt history stays in the mod's local store on your machine.
  • Per repo, which MCP servers and plugins were loaded and used: names, counts and dates, never tool arguments.
  • Learn mode lessons are kept there too: topic, time, repo name and the fact text, never your prompt text. The last 20 of each topic.
  • Costs are local estimates from built-in prices, not your bill.
